# Contributing to refreSSH

Welcome! This guide is designed for both human contributors and AI agents. It outlines our standards, workflows, and expectations.

## Core Mandates
- **Branding:** Use "refreSSH" (proper casing) in all documentation and UI text.
- **Usability & Security:** Always consider these first. If a design is unclear, ask. If it can be improved, suggest.
- **Security First:** Bind APIs to `127.0.0.1` by default. No sensitive data in logs.

## Technical Standards
- **Language:** Go (Golang). Use idiomatic patterns and the standard library where possible.
- **OS Support:** Windows, Linux, and macOS. Use platform-specific code (`_windows.go`, `_unix.go`) only when necessary, hidden behind clean interfaces.
- **Configuration:**
  - Windows: `AppData\.refreSSH`
  - Linux/Mac: `~/.refreSSH`
- **Shell Commands:** 
  - Windows (PowerShell): Use `;` for chaining.
  - Unix: Use `&&` for conditional chaining.
  - *Note: Always check the OS before executing chained commands.*

## Workflow & Issue Tracking
We use **Beads (`bd`)** for all task tracking.

1.  **Claim:** `bd update <id> --claim` before starting work.
2.  **Branch:** Create a feature branch (e.g., `feat/feature-name`).
3.  **Implement:** Follow the Plan-Act-Validate cycle.
4.  **Verify:** Ensure tests pass locally and in CI.
5.  **PR:** Create a Pull Request via GitHub CLI (`gh pr create`).
6.  **Merge:** Only the maintainer merges PRs into `main`.

## Release Management
- **Versioning:** SemVer 2 standards. Starting at `v0.9.0`.
- **Commits:** Clear, concise messages.
- **Changelog:** Autogenerated based on beads using GitHub emojis.
